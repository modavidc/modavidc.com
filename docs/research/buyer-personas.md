# Buyer personas (agentes) + evaluación de la web actual

Fuente base: `ANALISIS_FEEDBACK_GEMINI_2.md` (secciones 1–4).

## Agentes (buyer personas)

### 1) Reclutador Técnico / Hiring Manager
- **Qué busca**: Rol “buscable” (Tech Lead/Backend/Cloud), stack, señales rápidas de seniority, impacto y experiencia verificable.
- **Qué le importa**: claridad, keywords, projects/case studies, fechas/roles.

### 2) Dev Senior “sin cariño”
- **Qué busca**: señales técnicas reales, rigor, evidencia (diagramas, repos, decisiones), y estética que “huela” a ingeniería (no marketing).
- **Qué le importa**: credibilidad y densidad técnica (menos claims, más pruebas).

### 3) Founder / CTO de Startup
- **Qué busca**: ROI, velocidad, reducción de costo/riesgo, capacidad de destrabar deuda técnica y entregar.
- **Qué le importa**: métricas, oferta clara, CTA para agendar/consultoría.

### 4) Alguien NO técnico
- **Qué busca**: entender “qué haces por mí” en lenguaje humano, sin jerga, y qué resultado obtiene.
- **Qué le importa**: beneficios concretos, proceso simple, ejemplos.

## Preguntas: ¿la página actual cumple?

Evaluación basada en el hero actual (rol + badges + propuesta) y secciones “Impacto Medible” y “Proyectos Destacados”.

- **¿Entiendo qué resuelves en 10s?**: **Sí para técnicos (Recruiter/CTO)**, **parcial para no técnicos** (aún hay jerga: “legacy”, “APIs”, “ROI”, “cloud”).
- **¿Te contrataría?**: **Sí** (muy fuerte para consultoría/optimización por métricas), pero faltaría un CTA tipo “Agendar consultoría” arriba si el objetivo es convertir.
- **¿Qué quitaría de la web?**: para “Dev Senior” y “Recruiter”, lo más probable es **decoración** (gradientes/ornamentos) y elementos que distraen del valor (p.ej. el bloque de “disponible/no disponible” si no suma conversión).
